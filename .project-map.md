# Project Map

> Navigation cache. Source files are authoritative.

## Project
Local-first MCP server for navigating and maintaining arbitrary hierarchical documentation stored in Git-friendly local repositories.

## Areas
- `src/entrypoints/mcp/` — MCP tool registration, schemas, and protocol mapping; start: `mcp-server.ts`
- `src/application/` — one use-case function per documentation operation; persistence boundary: `ports/documentation-store.ts`
- `src/domain/` — source/node data contracts
- `src/infrastructure/filesystem/` — filesystem repository persistence and hierarchy semantics; start: `filesystem-documentation-store.ts`
- `.github/workflows/` — CI and GitHub Release → npm publishing automation
- `test/` — filesystem behavior, MCP protocol, and package identity tests

## Ownership
- `main.ts` — parses `DOCNAV_REPOSITORIES`, wires filesystem storage to stdio MCP transport, owns shutdown
- `mcp-server.ts` — registers eight namespaced `docs.*` MCP tools and retrieval-first server instructions
- `ports/documentation-store.ts` — application-owned persistence contract shared by all operations
- `filesystem-documentation-store.ts` — source/node CRUD, multi-repo lookup, pagination, raw-content files, parent relationships, recursive-removal semantics, cycle validation
- `filesystem-records.ts` — persisted source/node JSON schemas and canonical ID validation
- `package.json` — npm identity, npx binary, public package contents, build/publish lifecycle
- `publish.yml` — validates release tag/version and publishes the public scoped package with npm provenance

## Routes
- add/change an MCP tool -> `entrypoints/mcp/<operation>-tool.ts` -> `application/<operation>.ts` -> `ports/documentation-store.ts` -> `filesystem-documentation-store.ts`
- change storage layout or hierarchy behavior -> `filesystem-documentation-store.ts` -> `filesystem-records.ts`
- change startup/repository configuration -> `main.ts`
- verify MCP surface/argument mapping -> `test/mcp-tools.test.ts`
- verify persistence and graph behavior -> `test/filesystem-documentation-store.test.ts`
- change npm/npx packaging -> `package.json` -> `README.md` -> `.github/workflows/publish.yml`
- change advertised package/server version -> `package.json` + `index.ts` -> `test/package-metadata.test.ts`

## Flows
- MCP request: tool handler -> application operation -> `DocumentationStore` -> filesystem adapter -> JSON metadata / raw `.content` files
- retrieval: `docs.sources.list` -> `docs.nodes.list_children` -> `docs.nodes.fetch_content` -> filesystem adapter
- ingestion: `docs.sources.create` / `docs.nodes.add` / `docs.nodes.update` / `docs.nodes.remove` / `docs.sources.remove` -> filesystem adapter

## Invariants
- Public MCP tools use the `docs.sources.*` / `docs.nodes.*` namespaces; metadata instructs agents to query prepared docs before external crawling.
- Node IDs are canonical identity; titles may duplicate.
- `parentIds` allows arbitrary depth and multiple parents, but updates must remain cycle-free.
- Raw documentation is stored separately from navigation metadata in `.content` files.
- Multiple configured repositories are aggregated for reads; new sources are created in the first configured repository.
- Recursive removal deletes descendants only when all of their parents are already being removed; shared descendants survive through remaining parents.
